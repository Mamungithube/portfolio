ChatterBee Backend

Empowering Non-Verbal Speech Communication via Multilingual AAC Symbols & Caregiver Networks

View on Google Play Store View on GitHub

Project Overview

ChatterBee is an Augmentative and Alternative Communication (AAC) platform backend engineered to empower non-verbal and speech-impaired individuals (Communicators) to express thoughts, needs, and feelings through visual symbol cards, multi-language TTS audio playback, customized categories, and a caregiver monitoring network.

Built with Django 5.2 and Django REST Framework, the backend provides caregiver-communicator role hierarchies, real-time Firebase FCM emergency alerts, automated symbol CSV imports, multilingual card models powered by django-parler, and custom DRF security throttling layers.

Key Features

Caregiver-Communicator Hierarchy & Auth

Caregivers can create and manage dependent profiles, configure personalized symbol boards, and monitor activity. Supports JWT Auth (SimpleJWT) and Social Logins (Google/Apple via django-allauth).

Multilingual Symbol & Audio Engine

Multi-language card translations using django-parler with associated audio clips for QuickSpeaks, categories, and items. Features automated CSV bulk import tools for fast symbol catalog onboarding.

Real-Time FCM Alerts & Cloud Integration

Integrated with Firebase Admin SDK and Cloud Firestore for instant Emergency Alerts, Button Alerts, and real-time audio pinning between communicators and caregivers.

Speech & Activity Analytics Tracking

Tracks communicator usage statistics, most frequently spoken QuickSpeaks, and daily interaction trends to help caregivers and therapists assess communication growth.

Custom DRF Throttling Layer & OpenAPI Docs

Implemented custom rate-limiting (StaffExemptUserThrottle) protecting public APIs from abuse while granting exempt status to internal staff, coupled with OpenAPI 3.0 documentation (Swagger & ReDoc).

Technical Highlights & Optimization

N+1 Query Elimination & Bulk Endpoint Optimization

Replaced sequential database queries on nested categories/subcategories using prefetch_related and nested bulk serializers — slashing over 180+ individual network requests down to 1 high-performance bulk API payload.

Granular Throttling Security Architecture

Designed custom DRF throttling rules ensuring standard API consumers adhere to strict request quotas, preventing denial-of-service attempts while bypassing limits for staff dashboards.

Scalable Asynchronous Task Queue

Orchestrated Celery workers and Celery Beat backed by Redis for offloading push notification dispatches, periodic analytical rollups, and audio file indexing.

Production Multi-Container Setup

Complete Docker Compose environment encapsulating Gunicorn web server, Celery Workers, Redis Broker, PostgreSQL database, and Nginx reverse proxy.
